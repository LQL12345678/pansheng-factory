## 企业微信通知优化为纯文本格式

### 问题描述
手机微信收到企业微信 Webhook 通知时显示「暂不支持此消息类型」。

### 原因分析
企业微信 Webhook 发送的 `msgtype: "markdown"` 消息，在个人微信客户端无法渲染。

### 解决方案
修改 `backend/services/wechat.js`，所有通知改为**只发送纯文本** (`msgtype: "text"`)。

### 修改内容
1. **删除所有 Markdown 格式构建代码**
   - 移除 `formatRepairMessage`、`formatRepairCompletedMessage` 等旧函数
   - 新的 `buildRepairMessages`、`buildRepairCompletedMessages` 等函数只构建纯文本

2. **简化 `sendWechatMessage` 函数**
   - 原来双发（Markdown + 文本）
   - 现在只发送 `msgtype: "text"` 消息

3. **覆盖的通知类型**
   - 🔔 新工单报修通知
   - ✅ 工单完结通知
   - 🔧 备件领用审批通过
   - 📋 备件领用申请
   - ✅ 测试通知

### 效果
- 企业微信客户端：正常显示纯文本
- 个人微信客户端：正常显示纯文本
- 两边都不再出现「暂不支持此消息类型」

## 企业微信通知报修时间精确到秒（2026-05-19）

### 问题描述
用户要求企业微信推送的工单通知中，报修时间需要精确到秒。

### 原因分析
之前的通知代码中，报修时间使用 `report_date`（仅日期）和 `report_time`（可能仅精确到分），不满足精确到秒的要求。

### 解决方案
修改 `backend/services/wechat.js`，将报修时间改为使用 `created_at` 字段（数据库默认值 `datetime('now', 'localtime')`，格式为 `YYYY-MM-DD HH:MM:SS`，精确到秒）。

### 修改内容
1. **定时提醒通知**（第54行）：`r.created_at || r.report_date || ''`
2. **新工单报修通知**（第72行）：`repair.created_at || ''`
3. **工单完结通知**（第111行）：`repair.created_at || ''`

### 效果
- 企业微信通知中的报修时间现在显示为 `2026-05-19 10:02:28` 格式，精确到秒。
- `created_at` 由数据库自动生成，格式为 SQLite `datetime('now', 'localtime')` 标准格式。

## 全屏显示功能（2026-05-19）

### 需求
在系统顶部栏添加全屏切换按钮，方便大屏展示数据看板。

### 修改文件：`frontend/src/App.tsx`

**新增功能：**
- 顶部栏右侧新增全屏切换按钮（🖥️ / 📺）
- 使用浏览器原生 Fullscreen API（`requestFullscreen()` / `exitFullscreen()`）
- 监听 `fullscreenchange` 事件，同步 React 状态
- 按钮样式与整体深色主题一致（半透明背景 + hover 效果）
- 移动端自动隐藏（移动浏览器对 Fullscreen API 支持有限）

**实现代码要点：**
```tsx
const [isFullscreen, setIsFullscreen] = useState(!!document.fullscreenElement);

// 同步全屏状态
useEffect(() => {
  const handleFsChange = () => setIsFullscreen(!!document.fullscreenElement);
  document.addEventListener('fullscreenchange', handleFsChange);
  return () => document.removeEventListener('fullscreenchange', handleFsChange);
}, []);

// 切换全屏
const toggleFullscreen = async () => {
  if (document.fullscreenElement) {
    await document.exitFullscreen();
  } else {
    await document.documentElement.requestFullscreen();
  }
};
```

## 数据看板自动隐藏侧边栏修复（2026-05-19）

### 问题描述
上次添加了"打开数据看板时自动隐藏侧边栏"的逻辑，但实际无效。
原因：桌面端 `.sidebar` 样式使用 `left: 0` 始终显示，且 `.sidebar.open` 在桌面端没有定义，导致 `sidebarOpen` 状态在桌面端完全不生效。

### 修复内容

**1. `dark-theme.css` — 桌面端侧边栏支持 open 类名控制**
```css
.sidebar {
  ...
  transform: translateX(-100%); /* 默认隐藏 */
  transition: transform 0.3s ease;
}
.sidebar.open {
  transform: translateX(0); /* 显示 */
}
```

**2. `dark-theme.css` — 桌面端也显示汉堡按钮**
```css
.menu-toggle {
  display: block; /* 原为 none */
  ...
}
```

**3. `App.tsx` — sidebarOpen 初始值改为按屏幕宽度判断**
```tsx
const [sidebarOpen, setSidebarOpen] = useState(window.innerWidth > 768);
// 桌面端默认展开，移动端默认收起
```

**4. `App.tsx` — 完善路由切换逻辑**
```tsx
useEffect(() => {
  if (pathname.startsWith('/stats')) {
    setSidebarOpen(false); // 进入数据看板，收起
  } else {
    // 离开数据看板，桌面端自动展开
    if (window.innerWidth > 768) {
      setSidebarOpen(true);
    }
  }
}, [pathname]);
```

### 最终效果
- 桌面端：侧边栏默认展开，可通过汉堡按钮切换显示/隐藏
- 移动端：侧边栏默认收起，通过汉堡按钮打开
- 进入 `/stats` 页面：侧边栏自动收起
- 离开 `/stats` 页面：桌面端自动展开侧边栏

## 布局修复 - 侧边栏和内容区 Flex 方案（2026-05-19）

### 问题描述
1. 数据看板页面点击汉堡按钮没反应
2. 其他版块右侧有空白区域，内容没有铺满

### 根因分析
1. `dark-theme.css` 中桌面端 `.sidebar` 没有设置 `width`，导致宽度无法控制
2. 侧边栏和内容区的布局在桌面端没有明确分配宽度

### 修复内容

**1. `dark-theme.css` — 给 `.sidebar` 添加明确宽度**
```css
.sidebar {
  width: var(--sidebar-width);
  flex-shrink: 0;
  transition: width 0.3s ease, opacity 0.3s ease;
}
```

**2. `App.tsx` — 添加桌面端 media query 覆盖样式**
在 `<style>` 标签中添加 `min-width: 769px` 的桌面端规则：
```css
@media screen and (min-width: 769px) {
  .app-body {
    display: flex;
    margin-top: var(--topbar-height);
    min-height: calc(100vh - var(--topbar-height));
  }
  .sidebar {
    width: var(--sidebar-width);
    flex-shrink: 0;
    transition: width 0.3s ease;
  }
  .app-body.no-sidebar .sidebar {
    width: 0;
    overflow: hidden;
    border-right: none;
  }
  .main-content {
    flex: 1;
    min-width: 0;
  }
}
```

### 最终效果
- 桌面端（>768px）：侧边栏占 240px，内容区自动填满剩余空间
- 点击汉堡按钮可正常切换侧边栏显示/隐藏
- 数据看板页面自动收起侧边栏，内容区占满全宽
- 其他版块（首页、设备台账等）：侧边栏展开，内容区铺满无空白

## 侧边栏固定定位（2026-05-19）

### 需求
页面滚动时，导航页（侧边栏）固定不动，不跟随页面一起滚动。

### 修复内容
在桌面端 media query 中将 `.sidebar` 改为 `position: fixed`：

```css
@media screen and (min-width: 769px) {
  .sidebar {
    position: fixed;
    top: var(--topbar-height);
    left: 0;
    width: var(--sidebar-width);
    height: calc(100vh - var(--topbar-height));
    transition: width 0.3s ease, opacity 0.3s ease;
  }
  .main-content {
    margin-left: var(--sidebar-width);
    transition: margin-left 0.3s ease;
  }
  .app-body.no-sidebar .sidebar {
    width: 0;
    opacity: 0;
  }
  .app-body.no-sidebar .main-content {
    margin-left: 0;
  }
}
```

### 效果
- 桌面端：侧边栏固定在视口，页面滚动时导航栏保持不动
- 移动端：保持原有的抽屉式侧边栏（position: fixed + transform）
