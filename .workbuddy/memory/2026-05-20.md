## 修复超级管理员无法打开用户管理页面
- **错误**：登录后点击"用户管理"立即跳回首页
- **根因**：`UserManagement.tsx` 和 `NotificationSettings.tsx` 用 `window.location.href = '/'` 做权限重定向。页面首次加载时 `user` / `isSuperAdmin` 初始为 `null` / `false`，useEffect 立即触发了全页跳转。即使后续 `checkAuth()` 恢复正确状态，`window.location.href` 硬跳转已经发生，再也回不来。
- **修复**：
  - 改用 `useNavigate()` + `navigate('/', { replace: true })` 做 SPA 内导航，避免全页刷新
  - 增加 `authChecked` 守卫：`if (!authChecked) return;`，等认证状态确认后再判断权限
- **修改文件**：
  - `frontend/src/pages/UserManagement.tsx`
  - `frontend/src/pages/NotificationSettings.tsx`
- **注意**：其他页面（HomePage、DeviceList 等）的 `window.location.href = '/login'` 不受影响，因为这些页面的渲染前提是 `user` 已存在，不会在首次加载时误触发。

## 修复 ZoneMap 热力图跨线串数据 Bug
- **bug**：`/api/repairs/zone-stats` 的 SQL 只有 `WHERE area IN (...)`，没有按 `line` 过滤，导致所有线体相同区域的工单被汇总到一起
- **根因**：重构 SQL 时（从 32 次查询改为 1 次）漏掉了 `line = ?` 条件
- **修复**：改为 `WHERE (line = ? AND area IN (...)) OR (line = ? AND area IN (...)) OR ...`，4条线体共4组组合条件
- **验证**：1线-老化房从 ~70+ 修正为 24，1线-后侧段 0 正确
- **修改文件**：`backend/routes/repairs.js`

## 语音播报：待处理工单到达时发出语音警报
- **功能**：首页每30秒轮询检测待处理工单数量变化，数量增加时通过浏览器 Web Speech API 播报3遍"您有新的待处理工单"
- **实现**：`prevPendingRef` 记录上次数量（初始-1首次不播报），`pendingCount > prevPendingRef` 时触发 `speakAlert()`
- **播报**：`speakAlert()` 递归调用3次，每次播完后触发下一次；`speechSynthesis.cancel()` 防止重叠
- **修改文件**：`frontend/src/pages/HomePage.tsx`
